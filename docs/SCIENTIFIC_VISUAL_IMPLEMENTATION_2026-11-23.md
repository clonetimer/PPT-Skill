# 科研插图语义规划：首轮实现与验证

日期：2026-11-23。版本：`7.7.0-dev`。

## 本轮解决的问题

主分支已经有较丰富的原生图元，但缺少从来源中的科学对象到实际图元的可执行入口。用户已安装的个人 Skill 则仍以 V3 固定图型库为主。这会让“图型选择”和“版式选择”提前，张量、邻域、汇聚、残差等信息容易退化为文字方框。

本轮增加如下路径，保留现有渲染器和答辩资源：

`来源阅读 → 带证据的 FigurePlan → 按运算选择图元 → FigureSpec → SVG / 原生 PPTX → 实际渲染复核`

来源阅读仍由模型或研究者完成。运行程序会检查所引用的文件字节、对象关系和可见图元，但不会自动理解任意程序或证明科学结论。

## 已实现

| 部分 | 实际行为 |
| --- | --- |
| 入口分流 | 分开源图重绘、方法重构、概念插画、定量图表和流程图。 |
| 来源约束 | 节点与边引用证据 ID；记录文件、SHA-256 和精确定位；图像证据须为可读取的图像或 SVG。 |
| 语义图元 | 支持张量、时序、卷积、嵌入、加法、图注意力、分组均值、拼接、映射、任务输出、门控及不透明模块，共 12 类。 |
| 未知细节 | 不填补邻接、头融合、维数、权重或卷积参数；图中保留必要的示意与未知说明。 |
| 连接关系 | 检查真实箭头、端点、断线、跨文字；加法输入必须到不同端点，门控阈值进入独立的上下控制端。 |
| 导出 | 同一编译结果生成 SVG 和可编辑原生 PPTX，并保存 plan、figure 和 review JSON。导出失败不会发布部分新文件覆盖上一组成功结果。 |
| 可复用入口 | 仓库 SKILL、指南和示例已接入新路径；个人 Skill 采用增量资源更新，保留原答辩素材。 |

源图重绘交给现有的来源专用 FigureSpec 路径，防止固定语义图元替换原图的独特结构。概念插画和定量图表分别交给图像生成工具与数据绘图路径；本程序不声称替它们完成了生成。

## 技术方案的依据

- [GAT 作者说明](https://petar-v.com/GAT/)用于核对邻域和多头机制应呈现什么。
- [PlotNeuralNet 作者代码](https://github.com/HarisIqbal88/PlotNeuralNet/blob/master/pycore/tikzeng.py)用于研究按算子区分几何表达；没有复制其代码。
- [ONNX 形状推断说明](https://onnx.ai/onnx/repo-docs/ShapeInference.html)用于明确未知维度与可推导维度的边界。
- [Graphviz dot 文档](https://graphviz.org/docs/layouts/dot/)用于评估布局方案。本轮保留显式坐标与折点，没有增加自动布局依赖。

选择沿用 Python / python-pptx 原生渲染，原因是现有组件可复用、科学标签可编辑、同一语义输入可生成一致的 SVG 与 PPTX。代价是首轮算子范围有限，布局仍需模型或研究者编排。

## 验证证据

新增 61 个 unittest 用例：规划 19、图元 21、编译与变异检查 21。项目原有 unittest 用例 101 个，以及一个独立的可编辑多边形回归脚本，均在本轮验证范围内。测试关注实际行为，例如删除某个头、删除邻域箭头但保留输入输出线、改错维数、删边、移动端点和让连接穿过文字；不会因 JSON 仍写着正确标签就判定通过。

独立代码审查发现的残差示例路由、失败导出混杂、伪图像证据、维度遗漏、已知节点长标签和审计漏洞均已增加针对性回归。实际视觉核对又暴露了加法与阈值输入共线的问题，因而增加独立端点规则。截图中的来源关系仍需独立读图核实：自动检查只能核对已输入的关系，不能发现未录入的来源事实。

两个公开合成案例为多头图注意力与残差分支。两个用户截图只作为本地回归输入，不提交截图及其研究结构到公共仓库。两类案例均经过原生 PPTX 导出和 LibreOffice PDF/PNG 检查；这不等于 Windows PowerPoint 宿主验收。

旧 Skill 的独立基线任务能够提出合适的科研图元，但缺少本轮可运行的编译入口。因此，本轮没有声称“旧 Skill 完全不会规划”或发布任何自动生成成功率。

## 复现

在仓库根目录运行：

```bash
python tools/test_scientific_figure_plan.py
python tools/test_scientific_figure_glyphs.py
python tools/test_scientific_figure_render.py
python tools/build_scientific_figure.py examples/semantic_figures/graph_attention.json --output-dir dist/semantic_demo
python tools/build_scientific_figure.py examples/semantic_figures/residual_branch.json --output-dir dist/semantic_demo
```

证据相对路径默认以 brief 所在目录解析。完整契约与自建示例见 [Scientific Figure Planning](SCIENTIFIC_FIGURE_PLANNING.md)。CI 执行新测试、构建两个案例，并上传其生成文件；CI 运行结论以对应 PR 检查记录为准。

## 实际边界

- `7.7.0-dev` 是可运行的有限实现，没有声明为稳定版本或自动源码解析系统。
- 用户截图回归只支持可见标签和箭头，尚未与论文和真实实现逐项核对。
- 已知邻域图元首轮支持最多 6 个节点；大图、未知算子、照片及独特源图构图使用来源专用路径。
- 多组池化与多类别输出使用明确标注的代表项和省略号，不伪造全量数据或概率。
- PPTX 的文字和形状可编辑；连接线使用固定坐标，拖动节点不会自动跟随。改变布局后应修改 brief 并重新生成。
- 图元最低字号检查不能替代最终版面检查。密集结构在论文单栏或投影片尺寸下仍可能需要拆图和重新排版。
- 自动 review 保持科学审查与视觉审查 `pending`。模型复核和 LibreOffice 预览不等于人工领域审查、期刊验收或目标 Office 宿主审查。

后续应优先拿真实源码和文章校对同一方法的对象、维度及依赖，再补充当前词汇覆盖不到的机制，并在目标版面尺寸下重新布局。
