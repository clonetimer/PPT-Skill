## R01–R09 are blocking rules, not style preferences

- **R01 Science and provenance:** inspect actual original figure, caption, method equations and relevant implementation. Freeze an inventory before drawing, including source locator, unknowns, parameters and tensor dimensions. Do not silently resolve source figure/text contradictions; record discrepancy and chosen evidenced reading. Invented scientific facts/data are blockers.
- **R02 Scientific graphical grammar:** inspect what actual shapes, color, grouping, overlapping boundaries, spatial references and repeated structures express. Preserve their scientific function; choose a source-specific mark rather than a generic box. Geometry should explain the mechanism. No automatic preference for photos, rounded cards, maximal detail or zero raster. If original has no visual figure, inspect a relevant scholarly reference and mark that gap. Form declarations are checked against actual editable objects, then visually reviewed. **Composition-level scientific grammar (Trial 30):** meaningful internal icons do not justify placing every object inside the same pale rectangular card. Before drawing, assign a semantic or readability role to every visible container/group boundary (e.g., actual subsystem membership, shared state, encapsulated abstract process, required panel separation). Prefer the scientific object itself, meaningful paths, whitespace or light separators as the composition's primary structure where appropriate; use local labels without a surrounding card when the object and label suffice. In the actual final-size preview, inspect repeated wrappers both individually and as a whole: if removing a wrapper preserves the scientific meaning, grouping and readability, omit it or replace it with a less dominant treatment. Preserve a source-required boundary, a genuine abstract block, an intentional region or a readable table when justified. Pastel fills, rectangles, orthogonal connectors and repeated geometry are not prohibited; neither a quota of nonrectangles nor a palette swap establishes scholarly quality.
- **R03 Operator-level completeness:** preserve meaningful layer names, sequence, parameters, dimensions, group boundaries, labels and interfaces. Distinguish essential from detail suitable for notes; every omission must be justified against the source inventory, not silently replaced by MLP/process. Symbols newly introduced have definitions/visual referents. Missing required label or mark blocks. **Figure–caption–body information allocation (Trial 32):** choose the figure's scientific question and intended use before drawing. For a paper figure, preclassify source-supported information as (a) indispensable in-figure identifiers, units, dimensions, symbols, operator/decision labels, legends and edge semantics; (b) caption-level decoding, notation definitions, and schematic/provenance qualifications; (c) body-level derivations, implementation details, parameter rationale and extended explanations. Retain every necessary scientific relationship and unambiguous identifier; move explanatory duplication or sentence-length prose to a supplied caption/body explanation, unless indispensable to decoding this specific figure. If an equation is the figure's mechanism or necessary to distinguish a decision/operation, keep its compact form; otherwise a short named operation and a source-linked explanation may suffice. Never omit safety/evidence qualifications needed to prevent misleading standalone interpretation. A presentation figure may instead use speaker notes or adjacent explanatory text according to audience and output contract. Do not confuse source inventory completeness with displaying every source fact inside the drawing. Record each material omission/relocation and its companion-text destination; do not claim a companion exists if it has not been delivered.
- **R04 Typed topology:** separate sum, multiply, gating, concatenation, weighted concatenation, average and true feedback. List every required directed edge with operand/control/weight/residual role and destination port; distinguish dimension and vector-field arrows from data connectors. Verify actual end points, direction, distinct operand ports and order. For every aggregation operand, freeze a planned normalized target anchor (x/y in [0,1] on the target mark's declared bounding box); native line routes must actually reach it, not merely touch any part of the correct operator. For freeform paths, review actual geometry against the same planned anchor. For custom freeforms verify visually against exact source/equation; machine checking declared bindings alone cannot establish true topology. Crossings are allowed if scientifically necessary, not accidental junctions; prevent floating, misdirected and hidden arrows. Set visible line weight and arrowhead in final display.
- **R05 Notation and final-size legibility:** preserve bold/italic/roman, case, index and math roles. Use actual final slide placement, not source canvas size. Default provisional floors for presentation: rendered span >=11 pt, core labels >=14 pt; prioritize main labels around 18 pt where space permits. These are engineering floors, not guaranteed readable in all rooms. No silent lowering to fit; reallocate space or separate detail. Publication output requires named venue, actual physical dimensions and explicit thresholds. Check nested scripts, glyph substitutions, arrowheads and raster labels on actual PDF/PNG; verify font/host where possible. Use real final-size preview, not just enlarged figure.
- **R06 Layout:** allocate region and label bands before detailed drawing; check full figure and dense regions. No unjustified overlap, clipping, wire through text, tiny controls, or crowding next to useless empty space. Preserve intentional grouping/overlap; no arbitrary equal-size boxes or global occupancy targets. Automatic PDF text-box intersections are conservative proxies; inspect actual shape/text occlusion, hierarchy and spacing. Compare the whole-image hierarchy with the source, not only a glyph crop: a scientifically meaningful data mark should not become a small decorative icon inside a visually dominant generic card. Retain meaningful grouping and readable task/feedback direction when simplifying wrappers. Record the wrapper-removal test and any justified retained boundaries in the R02/R06 visual review. At final size, apply a separate redundant-text removal test to every explanatory phrase: if moving it to the accompanying caption/body/notes leaves the intended module function, decision, routing and scientific claim decodable, relocate it rather than shrinking the typography or filling useful whitespace. Compare diagram-only readability before/after, trace input-to-output and conditional branches, verify concise labels remain associated with modules, and supply the relocated content. Record retained critical text, moved text, destination and remaining decoding ambiguity in the R03/R06 review. There is no universal word-count limit and no blanket prohibition on formulas or labels.
- **R07 Editable deliverable and evidence:** exact scientific geometry/text native/editable when requested. Keep genuine photos, data plots and spatial references only when they serve the scientific explanation, with provenance and hashes. Never use a pasted whole network image or fabricated measurements to pass. Native-object count and image area are descriptive, not quality scores. Editable freeforms are not necessarily auto-reconnecting connectors or native equations; disclose. Preserve source-derived illustrative vs actual data distinction.
- **R08 Revision and release:** preserve frozen original preview, source contract, mapping and user judgment. For local changes, list mutable shape IDs and preserve other native objects and assets; inspect rendered change scope. Re-prepare after any changed source/mapping/PPTX. Retain original and new render, source-linked review observations, current limitations. Do not mark user approval without actual user feedback.
- **R09 Semantic shape grammar and legend decodability:** different computational block types must not collapse into one repeated generic glyph solely for stylistic consistency. Give each source-defined operation a distinct, meaningful visual encoding (geometry, internal operator mark, or an explicit combination) and a nearby label/compact legend that maps the encoding to its function. Different shapes alone are not enough: a reader must be able to decode what each block does without guessing. Color alone is insufficient when the shapes remain interchangeable or the palette is not reliably distinguishable. Branch split, voxel-wise addition, residual path, downsampling, upsampling and basic convolution must remain semantically distinct when present. Extend the same rule to distinct source-defined data and artifact types: raw documents, structured records/storage, unstructured text, graphs/subgraphs, syntax trees, models and other actual objects. Before drawing, inventory these types and their visual encodings; distinguish raw documents from extracted unstructured text, structured data from unstructured data, and graph topology from hierarchical trees when the source makes those distinctions. Use internal marks that express structure where supported (e.g., rows/fields, text lines, nodes/edges or tree branches), not merely different colored boxes; a database cylinder denotes storage, not all structured data. Reuse a glyph consistently for the same semantic class, while adding local role labels for distinct instances. Do not invent topology, schema, model internals or data in order to decorate a glyph; explicitly mark schematic content. For acceptance, select at least one example of every source-defined operation AND data/artifact type, compare the frozen inventory to the actual final-size render, and ask a reader to distinguish confusable pairs and identify their functions from meaningful geometry/internal marks plus labels or a compact legend. Unexplained or visually interchangeable semantically distinct types fail R09. Ordinary process rectangles remain acceptable for genuine abstract operations; distinctiveness is not a requirement for arbitrary unique shapes. Inspect each glyph in its enclosing composition too: unnecessary repeated card wrappers must not obscure the distinction between source-defined object types (see R02/R06). A reader's ability to identify AI authorship is distinct from academic usability; do not reject or approve the latter on origin recognition alone.

## Executable finalization (all drawing routes)

Existing build tools remain draft generators; the gate is the final handoff path for scientific figure/single-page PPTX work. It is deliberately small, works with the existing native renderer or a source-specific PowerPoint script, and does not constrain figure vocabulary.

1. Before drawing, save source.json with actual evidence copies (paths relative to source.json, SHA-256, locators), source-derived marks/typed relations, and placement. Do not derive the inventory from the draft or backfit it after an error. If source content cannot be inspected or a conflict remains material, stop at draft.
2. Draw, then bind the source inventory to actual top-level PPTX shape IDs (one or more per mark/route). Use required shape kinds, labels, actual route segments, distinct ports, and operand order. Nested group geometry and freeform route direction require visual review; do not claim automatic validation of them. Inspect both original and final-size preview.
3. Run prepare; fix all machine findings or keep draft. Write the nine specific review observations from exact receipt, original evidence and actual PDF/PNG. A review is an author/independent-agent/human/user review, not an automatically inferred scientific truth; say who performed it. No checkbox-only approval.
4. Run finalize to publish the candidate and hash-bound receipt. Re-review on any change. Candidate is not user acceptance; preserve physical projection and Office compatibility limitations.

```bash
python -m pip install python-pptx pymupdf
# LibreOffice Impress must be installed and available on PATH.
python tools/academic_delivery_gate.py prepare --pptx draft.pptx --contract source.json --mapping mapping.json --review-dir review
# inspect review/render.pdf and review/final_size.png and author review/checked.json
python tools/academic_delivery_gate.py finalize --pptx draft.pptx --contract source.json --mapping mapping.json --review-dir review --review review/checked.json --destination delivery/figure.pptx
```

See the complete small, synthetic input example generated in tools/test_academic_delivery_gate.py. Field contract:
- source.json: version=1, claim, mode, evidence [{id,kind,path,sha256,locator}], marks [{id,evidence,locator,meaning,form,native_kinds,labels,core?,operator?,operands?}], relations [{id,evidence,locator,meaning,source,target,role,target_port,directed,target_anchor?}], placement {profile,width_in,height_in,min_span_pt?,min_core_pt?,venue?}, all_native optional. Evidence kind visual_reference plus paper/code/data/user_spec required. For aggregation, operands is the ordered list of incoming relation IDs; each of those relations must include target_anchor [u,v] in normalized target-mark coordinates. This is a layout/semantic plan made before drawing, not a measurement copied from the generated line. Native straight route endpoints are checked against it; freeform paths require render review. Other relations can optionally provide a valid target_anchor. Shape kind names are MSO_SHAPE_TYPE names, optionally AUTO_SHAPE:MSO_SHAPE name.
- mapping.json: marks keyed by source id {shape_ids,form,operator?,operands?}; relations keyed by relation id {shape_ids,source,target,role,target_port,directed,arrow_shape_id?}. For native straight routes, shape_ids are ordered connectors from start to finish; arrow is native tailEnd or an actual editable marker ID near endpoint. Custom paths are flagged for R04 review. assets keyed by each picture shape id {category,evidence,locator,sha256}. Local revision additionally records revision {baseline,sha256,mutable_shape_ids}.
- checked.json: {receipt_sha256,reviewer_role,checks:{R01..R09:{status:"pass",locator,observation}}}. Locate actual checked scientific content and rendered region, including justified simplifications. Reviewer role must be accurate.

Machine checks: frozen evidence hash, exact source-to-object coverage, native kind, required label, typed relation bindings and straight-line geometry, operand endpoints, actual retained picture digests, local unchanged XML, render actual size/label coverage, text intersection proxy, immutable prepared artifact/review. R09 is a mandatory human/agent visual-grammar review: document the source-derived operation/data/artifact type inventory, actual glyph bindings, representative confusable pairs and legend/label decodability. The machine cannot infer whether two glyph classes are semantically distinguishable or whether a legend is immediately decodable. Review checks also include actual scientific validity, notation, custom paths/arrow direction, grouping, projection readability incl. raster labels, crowding, intentional overlap and photo provenance. Neither alone is sufficient. A developer can still call draft renderers; this is a delivery-path gate, not a universal filesystem policy or a proof of visual quality.

CI uses a real synthetic PPTX -> LibreOffice PDF and mutation tests for missing layers, wrong shapes, wrong operator/port, missing or disconnected arrows, shrinking, overlaps, stale source and missing review. Historical feedback motivates the tests; synthetic mutations do not mean all 20 historical slides have passed the gate. No extra model training, no source data sent to public repo.
