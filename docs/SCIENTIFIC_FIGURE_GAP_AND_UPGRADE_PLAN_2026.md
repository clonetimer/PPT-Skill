# 科研绘图差距与升级方案（2026-11-07）

> 本文的“当前差距”记录升级前的 V7.5 基线。V7.6 开发版已实现 FigureSpec 证据契约、C01 可见连线校验、六类 Iris 定量图、CC0 图像与像素统计复合图、两套输出 profile、Nature 双栏尺寸示例和 14 任务基准合同。独立领域的先评后核对、实际投影/印刷终尺寸复核与目标期刊的最终投稿核验仍待执行；先评只对基准预期和实现说明设盲，文件名或来源可能透露版本。状态以仓库 README 和 `dist/render_record_v76.json` 为准。

## 结论与适用边界

当前 Skill 已能从 JSON FigureSpec 生成可编辑的科研方法示意图，并完成 SVG/PPTX 结构审计；其成熟场景是**学术答辩中的方法与工程流程图**。它还不能通用地承担定量结果图、显微/实验图像、统计多面板图或投稿级图件的制作与验收。下一步应补齐证据、数据、语义、可访问性和交付契约，再扩展图形数量。

应分开两种输出模式：`presentation` 面向投影观看和演讲节奏，`publication` 面向目标期刊的最终尺寸、图注、数据与图像完整性要求。期刊的 5 pt 最低文字要求不能直接套用到答辩投影；答辩现有 9.5–11 pt 技术标签也不应仅凭 PPTX 无越界就判定可读。不同目标期刊的具体要求须在任务开始时核对其当前作者指南。

## 仓库证据与差距

| 领域 | 已有能力 | 可核查的不足 | 优先级 |
|---|---|---|---|
| 图形覆盖 | 5 个 FigureSpec，涵盖工程流程、时序网格、C01 方法图与复合页 | 没有由原始表格生成的定量结果图、统计分布图、实验照片/显微图、多模态图 | 高 |
| 科学证据 | C01 记录 DOI、证据边界与 schematic 替代；DeckSpec 有 claim/evidence | FigureSpec 无统一 JSON Schema；多数元素没有逐项来源、置信度和允许变换；C01 的 `semantic_edges` 是声明，验证器尚未由实际连线几何独立求证 | 最高 |
| 定量规范 | 文档提出“一页一结论”和来源状态 | 无数据表→变换→图形的链；缺轴单位、样本量/重复定义、误差条、统计检验、数据拆分/随机种子等结构字段与检查 | 最高 |
| 图像完整性 | 允许真实照片作为栅格；原图不随仓库分发 | 无原图哈希、裁剪/拼接/伪彩/LUT/比例尺/图像分析处理日志，也无代表性图像与量化结果的关联 | 高，按场景启用 |
| 可访问性 | 字体范围、文本碰撞和越界审计 | 无实测对比度、灰度/色觉模拟、线型或符号冗余编码、复杂图的文字说明；当前审计未测投影观看距离 | 高 |
| 工程与复现 | 同一 FigureSpec 双渲染、Windows PowerPoint 验证过 C01、CI 检查 SVG/PPTX | 无规范化数据/环境/生成版本记录和视觉回归；Windows 渲染只覆盖 C01 复合页；`README` 仍把已合并的主线称为 branch，组件目录仍称 B01/F07 才由 FigureSpec 驱动 | 中 |
| 评价 | 结构检查与 C01 人工渲染检查 | 缺多学科固定任务集、盲评、失败样例和发布前硬门槛；对象数不能代表科学或视觉质量 | 高 |

以上“没有”是针对当前仓库文件和校验脚本的结论，不等于项目作者在仓库外没有相应素材或流程。Nature 等期刊规范也不能替代各学科自己的报告标准。

## 目标架构

保留 `DeckSpec → SlideSpec → FigureSpec → SVG/PPTX/PDF` 主链，在 FigureSpec 前增加 `FigureContract`，并将数据/图像及证据与几何分开：

```text
研究来源 ──> EvidenceRecord ──> FigureContract ──> ScientificIR ──> Layout/Style ──> Render
                 │                  │                 │                              │
                 └─ DOI/页码/图号    ├─ 结论/面板角色   ├─ 节点/边/公式/单位             └─ SVG/PPTX/PDF
                                    └─ 数据与图像约束  └─ 原始数据或图像引用
```

- `FigureContract`：一句可辩护的结论、图件类型（定量组合/机制主导/图像+定量/混合）、面板与证据的映射、目标受众/载体、最终尺寸、审稿风险。
- `EvidenceRecord`：来源标识、定位信息、证据级别、许可/再利用边界、原文件哈希、未验证项。重要标签、公式、数值和拓扑边应能追到具体记录。
- `ScientificIR`：类型化节点和有向边、公式、数据系列、轴/单位、统计定义、图像处理记录。禁止通过渲染器默认值偷偷补造科学含义。
- `StyleSpec` 与 `SourceStyleSpec` 只控制视觉编码；不得改变 ScientificIR 的科学关系。`LayoutSpec` 控制面板位置和演示密度。
- `RenderRecord`：生成脚本版本、依赖版本、输入哈希、输出哈希、渲染器、字体替换和 QA 结果。保留可复现构建命令。

## 分阶段实施与验收

### A．先封住错误结论与陈旧文档

1. 为所有 FigureSpec 加统一 Schema 和迁移器；元素有稳定 ID、语义类型和来源引用。把 C01 `semantic_edges` 与可见连接器关联，验证器从绘制关系独立检查路径和箭头方向。
2. 加负向测试：删边、反向边、交换 SR/EA 标签、改公式或数值时必须失败。记录“人工核验”与“自动通过”的不同证据等级。
3. 修订主线 README、组件目录和已过时的 QA 状态；旧报告明确标注历史版本。

**验收：**5 个现有 FigureSpec 全部迁移且可重建；关键关系的故意错误被 CI 拦截；新旧 SVG/PPTX 的科学标签一致；历史资料不再被误读为当前状态。

### B．建立数据驱动的定量图通道

1. 加 `DataSpec`：CSV/TSV 等原始数据引用、变量类型/单位、清洗与聚合步骤、样本和重复定义、训练/验证/测试划分、随机种子或折数。
2. 加 `ChartSpec`：图表类型、轴与量纲、尺度/零点、分组、中心统计量、分布/区间、误差条意义、比较对象和图注。先支持趋势+区间、分布/散点、点图或柱图、混淆矩阵、消融对比。
3. 生成图表时保持原始数据点和重要离群值可见；小样本不默认只给均值柱。图表选择从研究问题与数据类型出发，遵循目标学科惯例。

**验收：**至少 4 类真实脱敏数据任务可以从同一数据与配置复现 SVG、PPTX、PDF；图上每个数值可追到数据行和变换；缺单位、`n`、误差定义或关键来源时硬失败。[PLOS 对图形误导风险的讨论](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1003833)和[原始点/重复可见性的研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7265319/)可作为设计依据。

### C．补图像、可访问性与载体适配

1. 图像面板增加原图引用和哈希、裁剪/拼接/强度调整、伪彩/LUT、比例尺和量化链接；显微与医学图按领域规范额外检查。
2. 对关键文字、箭头和编码符号测对比度；做灰度与常见色觉差异预览。颜色之外增加线型、形状、直接标签；提供图的短说明和详细说明。
3. 两套输出 profile：答辩按投影尺寸检查，投稿按目标期刊最终尺寸与文件格式检查。SVG、PPTX、PDF 使用相同数据与 ScientificIR，字体替代和不同渲染器差异要留记录。

**验收：**至少一张“实验图像+量化”复合图具有完整处理记录；关键编码在灰度与色觉模拟下仍可区分；在最终投影/印刷尺寸人工复核通过。对比度阈值由项目定义，WCAG 只作为参考，不将其结果冒充期刊或 PPT 合规认证。

### D．固定基准集和发布门槛

建立 12–15 个可公开或授权使用的任务，覆盖论文图重绘、从论文构图、整套答辩、工程/物理机制、定量结果、消融、图像+定量；按学科和载体分层。每任务冻结来源、输入、预期科学关系、专家评分表与已知陷阱。每次升级比较：科学准确性、数据/图像完整性、可读性、可访问性、编辑/复现性和视觉质量。

**发布硬门槛：**关键科学边/公式/数据错误、来源状态不清、图像处理未披露、重要内容不可读或被遮挡，任一出现即不通过。自动校验负责可机器判定的部分；科学解释、图像代表性和受众理解由独立领域评审复核。平均分不能抵消硬门槛。

## 不纳入首轮的工作

不先扩充几十种固定版式或图标；不宣称“完全复刻”尚无高分辨率原图的 C01；不把 Nature 的单刊生产尺寸当作所有学科的通用标准；不以 0 越界或较低对象数替代科学和视觉审查。
